# M4 验收提示词

> 用途：把下面的提示词逐条粘进游戏聊天窗，按“预期”检查工具调用、UI 与数值。
> 覆盖 [m4a-verification.md](m4a-verification.md)、[m4b-verification.md](m4b-verification.md)
> 和 [m4-write-verification.md](m4-write-verification.md) 中尚未勾选的项。
>
> 标记说明：
> - **AI**：直接发给模型的玩家话术。
> - **MANUAL**：需要拆建筑、换档、抓包、重启或看日志，不是一句话能触发的。
> - 每条都尽量让模型走指定工具；如果模型换了等价工具，只要结果覆盖验收点即可。

## 0. 能力与目录

### A0 能力 / 工具目录

**覆盖**：M4a-11/13/14；M4-write-9/10/11

**MANUAL**

1. 进入存档，看 sidecar 日志里的 `hello.capabilities`：
   - 应含 `game.read.v1`、`game.entity.v1`、`game.progress.v1`、`game.view.v1`、`game.analyze.v1`、`ui.ask.v1`、`game.write.v1`。
2. 看 `ready.payload.tools`：
   - 只读：`game_get_overview/player/planet/power/research/production/entity/entities/progress/capture_view/analyze_area/...`
   - 写：`game_focus_camera`、`game_place_marker`、`game_open_panel`、`game_set_research`、`game_undo_last_write`
   - 本地：`kb_*`
3. 用旧版 mod（只声明 `game.read.v1`）连接：`ready.payload.tools` 不应出现 entity/progress/view/analyze/write/ask 工具。
4. 用未声明 `game.write.v1` 的 mod 连接：模型工具列表里不应出现 5 个写工具。

**预期**：能力、工具名与声明一致；没有“声明了但未实现”的工具。

## 1. M4a：截图、实体、进度

### A1 截图 + 模型描述 + 坐标 + 缩略图

**覆盖**：M4a-19/20/21/22/23/24/25

**AI**

> 看看我现在这片产线摆得对不对。请先截一张当前画面（不要带 UI），再描述画面里能看到哪些建筑、传送带和物流站，并告诉我你标注的编号和经纬度。

**预期**

- 调用 `game_capture_view`；工具卡标题为「截图」。
- 工具卡自动展开并出现缩略图；收起工具块后图片隐藏。
- 图片等比，不拉伸；截图里没有聊天窗、工具栏、小地图。
- 模型能描述画面内容，说明图片进了上下文。
- 返回的 `visibleEntities` 的 `x/y` 与图上建筑位置大致对齐。

### A2 截图性能 / 内存

**覆盖**：M4a-27/28

**AI**

> 连续截 5 张当前画面，不要分析，只确认截图成功。

**MANUAL**：截图后清空对话、滚动聊天记录，观察帧率与内存。

**预期**：连续 5 次帧率无明显下降、内存不持续增长；清空/裁剪后纹理释放、内存回落。

### A3 组装机详情

**覆盖**：M4a-37

**AI**

> 先列出我当前行星的组装机，取第一台，再查它的配方、每分钟产量、输入输出槽和供电情况。

**预期**

- 先 `game_get_entities`，再 `game_get_entity`。
- 配方名、`craftsPerMin`、输入/输出、功率与供电满足率与游戏面板一致。
- id 来自列表；不要凭截图猜。

### A4 分拣器目标

**覆盖**：M4a-39

**AI**

> 找一台分拣器，告诉我它从哪抓、送到哪，并和它实际连接的建筑对照。

**预期**

- `game_get_entities` 找分拣器，再 `game_get_entity`。
- `pickTargetName` / `insertTargetName` 与实际连接一致。

### A5 物流塔仓储

**覆盖**：M4a-40

**AI**

> 找一座物流塔，读它的仓储槽位前几项、供需模式和无人机/运输船状态。

**预期**

- `game_get_entity` 返回 `station.storage` 前几项与塔面板一致。
- 物流塔的槽位、供需模式、无人机/运输船数量与游戏面板一致。

### A6 回收 id / stale

**覆盖**：M4a-41

**MANUAL**

1. AI 提示词：

   > 列出我当前行星的组装机，并记住第一台的 entityId。

2. 拆掉那台组装机。
3. AI 提示词：

   > 用刚才那个 entityId 再查一次详情。

**预期**：返回 `reason=empty_slot` / `stale=true`，不返回旧机器数据，也不报未捕获异常。

### A7 远程行星未加载

**覆盖**：M4a-43

**AI**

> 查一个我当前没有加载工厂的远程行星的建筑详情；如果没有工厂，明确说明。

**预期**

- `available=false`、`reason=factory_not_loaded`。
- 不把它当成“0 栋建筑”或报错。

### A8 建筑列表 / 分页

**覆盖**：M4a-47/49

**AI**

> 列出当前行星所有建筑，先给第 1 页；如果 `hasMore=true`，按提示的 `offset` 继续，直到最后。

**预期**

- 不传过滤时 `total` 与游戏内建筑数量同量级。
- 连续翻页不重不漏。
- `hasMore=true` 时结果文本提示下一个 `offset`。

### A9 `protoName` 过滤

**覆盖**：M4a-48

**AI**

> 只列出当前行星的组装机，不要其他建筑。

**预期**：`game_get_entities` 的 `protoName=组装机` 生效，返回项全部是组装机。

### A10 `recipeId` 过滤

**覆盖**：M4a-48

**AI**

**预期**：模型先查 KB 取得 `recipeId`，再用 `game_get_entities` 过滤；返回项配方一致。

### A11 进度阶段 / signals / 里程碑 / 研究队列

**覆盖**：M4a-53/55/56/57

**AI**

> 我现在处于什么阶段？研究队列里有什么？最近的里程碑按时间倒序说，并解释每个 `signals` 布尔值的依据。

**预期**

- `stage` 与玩家自我认知一致（前期 / 行星内物流 / 星际物流 / 戴森球）。
- `signals` 与游戏实际进度一致（未解锁物流时不为 true）。
- `recentMilestones` 最近的在前。
- 研究队列与游戏面板一致。

### A12 只读工具回归

**覆盖**：M4a-61

**AI**

> 我的电够不够？铁块每分钟实际产多少？

**预期**：`game_get_power` 与 `game_get_production` 仍正常，数值与游戏面板一致。

### A13 知识库导出回归

**覆盖**：M4a-62

**AI**

> 查一下铁块用什么配方、需要哪些原料。

**预期**：`kb_search` / `kb_get` 可用；配方和原料来自知识库，不是模型记忆。

### A14 换档绑定

**覆盖**：M4a-63

**AI**

> 换档后重新问：我现在在哪颗行星，附近有多少建筑？

**MANUAL**：切换存档。

**预期**：新工具绑定到当前连接/当前存档；不返回上一个存档的建筑或历史。

## 3. M4 写操作：确认、令牌、工具、撤销

### W0 能力与工具目录

**覆盖**：M4-write-9/10/11

同 A0。重点确认 5 个写工具只在 `game.write.v1` 下出现。

### W1 确认 UI + 同意

**覆盖**：M4-write-15/16/17/18/19

**AI**

> 打开背包面板。

**预期**

- 先弹 `confirm_request`，不直接执行。
- `choose/question` 显示标题，`choose/explain` 显示详情。
- 右下角只有红色「拒绝」和蓝色「同意」；跳过/返回隐藏。
- 红按钮 hover 警告红、按下变暗；蓝按钮可点。
- 点「同意」：`confirm_result{allow}` → `tool_call game_open_panel` → 背包打开。

### W2 拒绝无副作用

**覆盖**：M4-write-19

**AI**

> 打开背包面板。

**操作**：点红色「拒绝」。

**预期**

- sidecar 收到 `confirm_result{deny}`。
- 模型看到 `confirmation_denied`。
- 背包没有打开，游戏状态无任何变化。

### W3 关窗 / Esc

**覆盖**：M4-write-21

**AI**

> 打开科技树。

**操作**：确认页出现后关闭聊天窗；再重试一次按 Esc。

**预期**：两次都按拒绝处理；科技树不打开；sidecar 不收到 tool_call。

### W4 60 秒超时

**覆盖**：M4-write-22

**AI**

> 打开星图。

**操作**：确认页出现后等待 60 秒。

**预期**：UI 自动收起，按拒绝处理；星图不打开。

### W5 令牌重放 / 参数篡改 / 过期

**覆盖**：M4-write-28/29/30

**MANUAL**（用 WS 抓包或测试客户端，不建议靠模型）：

1. 正常确认一次写操作，抓到 `tool_call` 帧。
2. 原样重放同一帧：mod 返回 `confirmation_invalid`，第二次不执行。
3. 修改 `args` 后重放：`confirmArgsHash` 不匹配，返回 `confirmation_invalid`。
4. 等 60 秒后重放：返回 `confirmation_expired`。

**预期**：三种情况都没有第二次副作用。

### W6 聚焦行星/星系

**覆盖**：M4-write-34

**AI**

> 先列出星球，再把镜头移到 `planet:102`（第二颗行星）。

**预期**

- 模型先查星球，再 `game_focus_camera{target: planetId}`。
- 确认后打开星图并定位到目标星系/行星。
- `game_undo_last_write` 后，如果星图原本没开则关闭；原本已开则保持。

### W7 聚焦建筑

**覆盖**：M4-write-34

**AI**

> 把镜头移到我当前行星的第一台组装机，用 `entity:<id>` 指定。

**预期**

- 确认后镜头移动到该建筑目标点。

### W8 新建标记 + 撤销

**覆盖**：M4-write-36

**AI**

> 在我当前站的位置做一个标记，文字写「M4验收标记」；地图简述只显示前两个字是正常的，完整名称应保存在标记详情。

**预期**

- 确认后标记出现在玩家附近，文字正确。

### W9 所有面板 + 撤销

**覆盖**：M4-write-37

**AI**（逐个测试，避免一次确认太多）：

> 打开科技树。
> 打开星图。

### W10 切换研究 + 拒绝 + 撤销

**覆盖**：M4-write-39

**预期**

- 同意后当前研究切换；拒绝后研究不变。

## 5. 记录建议

每条记录以下字段，便于回填验收清单：

- 提示词编号、游戏版本、存档
- 模型实际调用的工具名与参数
- 工具结果关键字段（不要贴完整大 JSON）
- UI 截图（确认页/工具卡/错误）
- 通过 / 失败原因

失败时优先保留 sidecar 日志中的 `callId`、`requestId`、`confirmToken` 指纹（不要记录完整 token）。
