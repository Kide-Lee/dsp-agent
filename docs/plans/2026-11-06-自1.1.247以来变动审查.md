# 自 1.1.247 以来的变动审查

- 审查范围：`22fc162`（release: 1.1.247）.. `600ed3c`（当前 HEAD）
- 规模：92 个提交、139 个文件、+13907 / −4147 行
- 审查方式：逐提交读 diff + 当前完整代码；以代码实现为准，不采信注释
- 验证：`verify.sh mod`、`dotnet run --project tests/ProtocolTests`、`cd sidecar && npm test` 均通过
- 未覆盖：Unity 编辑器内的 prefab 锚点 dump、AssetBundle 重建与实机截图（本次没有可用的 MCP for Unity 会话）

## 0. 结论

主干方向正确：多会话并行、蓝图 DSL/工厂出图、原生目标面板扩展、聊天窗左栏与 footer 这一轮的重构，整体抽象和离线测试都比 1.1.247 明显更完整，协议文档也先于代码更新。

但当前 HEAD **不适合直接发版**：

1. 有 7 个 P0 级问题：重新生成串会话、待办写存档绕过确认、并行确认面板互斥、蓝图编译绕过文件确认，以及工厂出图的三处硬伤（分拣器槽位、物流站 remoteRole、副产物只出一根分拣器）。后三处会让 `blueprint_compile` 和 `layout=factory` 产出的蓝图在游戏里不连通或停摆，而现有硬校验全部放行。
2. 有 11 个 P1 级问题，覆盖“已确认的写”“中断”“后台失败”“换档排队”“左栏绑定”等状态机闭环。
3. 1.1.298 发布后又有 41 个提交，版本号、CHANGELOG、校验和、README 全部没有跟上。

建议先修 P0，再决定 Harmony 补丁是否保留，最后统一做一次 1.1.299 的发布收尾。

## 3. 问题清单

### P0-1 重新生成会串到别的会话，并永久丢掉原会话一轮

- 位置：`mod/src/IcarusII/Plugin.cs:1452`（点击时只保存 `text`）、`Plugin.cs:628`（回执到达后才用 `_chat.ActiveConversationId` 发新 prompt）
- 触发：点“重新生成” → `history.deleted` 回执返回前切到另一个会话
- 后果：新提问发到切换后的会话（错误计费、污染历史）；原会话的旧回合已经在 sidecar 删除且不会再补发，ChatWindow 也已经清空原会话助手侧，这一轮彻底丢失
- 修复：`_regenerateDeleteId` 同时保存发起时的 `conversationId`，回执后按该 id 发送；切换会话时取消或阻塞该操作

### P0-2 `game_todo_write` 以 risk 0 写存档，绕过确认钩子与令牌

- 位置：`sidecar/src/tools/write.ts:487-521`（`risk: 0`，描述写“不改变游戏状态”）；`mod/src/IcarusII/Game/Tools/GameGoals.cs:670-733`（`SaveStore` 写 `galacticDigital` 的 Global TodoModule）；`Plugin.cs:900`（只有 `Risk>0` 或 `WriteToolNames` 才校验令牌，该工具不在 `Protocol.cs:356-386` 的表里）
- 触发：任何一轮模型调用 `game_todo_write`
- 后果：写存档、注入 GoalProto/GoalData，全程不弹确认、不校验一次性令牌，和 AGENTS“写操作必须经过 sidecar 确认钩子 + mod 侧一次性令牌”直接冲突；工具描述也与实现不符
- 附带功能问题：该工具不在 `WriteToolNames`，`GameToolDispatcher` 的 5 秒读缓存不会失效；因此紧随其后的 `game_todo_list` 可能返回写之前的列表，回合末自动清空 `{todos: []}` 也可能命中上一次的缓存而不执行
- 修复：要么把待办改为纯 UI/内存状态、不写存档；要么按 risk 1 走确认与令牌。两条路都需要单独增加“清读缓存”的工具名单，不能靠 `WriteToolNames`（那会强制弹确认）

### P0-3 并行会话的确认页/作答面板没有按会话隔离

- 位置：`Plugin.cs:1016`、`1050`（全局只允许一个 `_confirmation.Current`）；`ChatWindow.cs:8540`（`ShowAsk` 只允许一个面板）；`Plugin.cs:2101`（切换会话不取消 pending）；`Plugin.cs:2160`、`2185`（开窗只补一个 deferred）
- 触发：A 会话弹着确认页/作答面板 → 玩家切到 B → B 也请求确认/作答
- 后果：B 的请求被 `busy` 直接拒绝（`confirm_result=false` 或 `tool_unavailable`），玩家从未看到 B 的请求；A 的面板仍然显示在 B 的会话上下文里，玩家可能在以为是在处理 B 的情况下同意 A 的写操作
- 修复：把 pending 请求按 `conversationId` 队列化；切换会话时隐藏/取消旧会话的面板，或禁止在有待处理请求时切换；至少要等旧请求结束再发新请求

### P0-4 `blueprint_compile` 未确认即写蓝图文件，且没有接入工具清单

- 位置：`sidecar/src/blueprint/dsl/tool.ts:82-93`（直接 `ws.write`，没有 `confirmFileWrite`）；`sidecar/src/blueprint/tools.ts:28`（`BLUEPRINT_TOOL_NAMES` 不含 `blueprint_compile`）；`sidecar/src/tools/registry.ts:878-884`（`LOCAL_WRITE_TOOLS` 不含它，风险显示为 0）；`registry.ts:875`（`ready.payload.tools` 不含它）
- 后果：
  - 本地写文件没有走 `confirmLocalWrite`，与 `blueprint_save` / `blueprint_generate` / `blueprint_fs` 不一致；
  - mod 的工具列表/设置页看不到它，或把它当成只读“其他”工具；
  - `docs/tools/` 和 `tools.json` 完全没有它，`test:tool-docs` 因为生成器没传 `store` 而漏测
- 附带功能缺口：`compileIr` 只消费 `target` 与 `options.assembler`，`raw` / `module` / `connect` / `group` / `station` / `constraint` 全部只给 W50x 警告；而工具提示词与示例（`docs/plans/examples/小型运载火箭-30-全珍奇.bp.js`）都鼓励使用这些语法，模型会生成一张忽略其意图的蓝图。DSL 也没有 `blueprint_generate` 的容量拆张与 8 秒预算，大产线会直接因硬校验失败或长时间阻塞 sidecar
- 修复：`createDslTool` 接收并调用 `confirmFileWrite`；把 `blueprint_compile` 加入 `BLUEPRINT_TOOL_NAMES` / `LOCAL_WRITE_TOOLS` / docs 生成器；在 M1 限制解除前，把提示词改成“只支持 target/options.assembler”，或对不支持的语法直接报错而不是静默出图

### P0-5 工厂布局对所有建筑套用固定分拣器槽位，分拣器插错口

- 位置：`sidecar/src/blueprint/emit.mjs:12`（只有一套 `SIDE_SLOT`）、`68-107`（`addSorter` 机器端固定 `±1`）、`sidecar/src/blueprint/factory.mjs:93-104`（所有 stage 无条件 `addSorter`）
- 触发：`blueprint_compile`（`dsl/compile.ts:47` 固定 `layout:'factory'`）目标包含 2308/2309/2310/2317/2901/2902；或 `blueprint_generate` 指定 `layout=factory` / auto 回落
- 后果：这些建筑的槽位表/落点与 2303 不同（例如 2309 下侧槽位 `{1:4,0:5,-1:6}`、上侧落点 +2；2310 只有 -2/-1 列），固定表会把分拣器插到没有口的位置或指向别的槽位，游戏里不连通或被拒；`validate` 仍然通过（见 P1-9）
- 修复：把 `dsp-handcraft/src/gamedata.js` 已验证的逐建筑槽位表并成一份数据，供 `factory.mjs` 与 `addSorter` 共用；不要用一套固定槽位

### P0-6 工厂物流站 `remoteRole` 全为 0，模块之间不会送货

- 位置：`sidecar/src/blueprint/factory.mjs:31-37`（`storageOf` 固定 `remoteRole: 0`）、`44`（输入/输出站都走这里）、`78`、`107`
- 对照：`sidecar/src/blueprint/layout.mjs:263-264` 的供料站是 `localRole 1 / remoteRole 2`
- 触发：任何 `layout: 'factory'` 的蓝图（DSL 全部走这条路径）
- 后果：存储格被配置成只能本地存取，前后模块的出料站/进料站之间没有无人机/运输船；整张图“有站但没有物流”，`validate` 看不到
- 修复：`remoteRole` 与 `localRole` 同步设置（输入站 2、输出站 1），并加一条出图后的角色断言

### P0-7 多产物配方只出一根按主产物过滤的分拣器，副产物永远留在机器里

- 位置：`sidecar/src/blueprint/factory.mjs:103`（单根 output sorter，`itemIdFilter: outputs[0]?.itemId`）、`sidecar/src/blueprint/layout.mjs:366`（同样只过滤 `stage.output`）；`layout.mjs:371-373` 却把 `stage.outputs` 全部计成带上负载
- 触发：2308（精炼油+氢）、2309（石墨烯/硫酸）等带副产物的配方
- 后果：副产物在机器里堆积，最终停摆；容量模型还算进从未上过带的物品，拆张/产能判断随之失真。`blueprint-emit.mjs` 第 7 组用了双产物精炼厂，但只断言 `validate.ok`，正好掩盖
- 修复：每个产物各出一根带 `itemIdFilter` 的分拣器（或一条带子 + 多根分拣器），并让容量模型只计实际会上带的产物

### P1-1 已批准的写脚本，玩家切走后被焦点门控卡死

- 位置：`sidecar/src/session.ts:1983-1995`
- 触发：readonly/limited 档；`run_script` 已通过脚本级确认；脚本运行中玩家切到别的会话。脚本内每个写调用固定 `risk: 2` 且带 `confirmToken`（`tools/script.ts:304-313`）
- 后果：`needsAttention` 只看 risk、不看 token，于是每个已获授权的写都进入 `waitForFocus`，默认等 10 分钟（`session.ts:466-470`），超时返回 `not_focused`；期间还被标成 `attention`，但根本没有确认页；脚本自身 120 秒预算也挡不住这段等待
- 修复：`needsAttention` 增加 `!options.confirmToken` 条件；已带有效令牌的调用不应再等待焦点或弹确认；等待焦点应受 `signal` 与脚本 deadline 约束

### P1-2 abort 打在排队/建会话阶段不会阻止本回合执行

- 位置：`sidecar/src/agent.ts:3200-3206`（只记录 `pendingAborts`）、`3306-3315`（设置 `abortRequested` 后没有 return，继续执行 `session.prompt`）
- 触发：同时跑满 3 个会话时的第 4 个 prompt，或 `ensureSession` 还在加载 SDK/创建会话时点中断；`onSaveChanged` / `abortAll` 对 `startingRuns` 走同一条路
- 后果：界面显示“已中断”，实际整轮 LLM 照常执行并落盘，最后按 interrupted 发终稿；玩家看到“已停止”，历史里却有一条完整回答
- 修复：`runOnce` 在 `pendingAborts` 命中后直接 return（并释放 slot/发 idle），不要进入 `session.prompt`；或在 `prompt` 后立即检查并丢弃结果

### P1-3 `game_copy_blueprint` 默认调用完全不持锁

- 位置：`sidecar/src/tools/locks.ts:140-142`；`registry.ts:207-209` 的 `planetArg` 是可选的
- 触发：并行会话 A 调 `game_copy_blueprint` 不传 `planetId`（提示词允许省略，默认当前行星），B 同时在同星球改配方/库存
- 后果：A 复制到半新半旧的建筑快照；正是锁注释里要防的场景，但默认路径没有保护
- 修复：缺省 `planetId` 时加当前行星锁（或保守加 `global`）；`factoryId` 分支目前全仓无人使用，可删除或补上真实工具

### P1-4 `game_place_marker` 的撤销会删错标记

- 位置：`mod/src/IcarusII/Game/Tools/WriteTools.cs:155-166`（不记录新 warning id）、`168-181`（`FindLocationWarningId` 取第一个 `LOCATION_SIGNALID`）
- 触发：玩家已有任意定位标记（行星视图右键；`TetherTools` 也用同一个 signal 判定 hover）→ 调 `game_place_marker` → `game_undo_last_write`
- 后果：撤销删的是玩家已有的旧标记，新标记残留
- 修复：`SetLocationTracking` 后记录本次新增的 warning id（可按 `objectId` 或创建前后 cursor 差分），撤销只删这个 id

### P1-5 收起/展开会话记录后，蓝条与记录行绑定失效（回归）

- 位置：`mod/src/IcarusII/UI/ChatWindow.cs:5999-6017`、`6019-6031`（先 `LinkTurnsToConversationRows` / `RefreshIndexSelection`，再 `BuildConversationRecords`）；`BuildConversationRecords` 在 `5713-5780` 销毁并重建行，没有重新 Link
- 触发：点状态图标收起再展开，或展开“其余 N 条”
- 后果：`entry.Link` 指向已销毁的 Text，右栏滚动时“当前记录染蓝”永久失效，直到下一次完整的 `RebuildConversationIndex`
- 修复：把 `LinkTurnsToConversationRows` + `RefreshIndexSelection` 移到 `BuildConversationRecords` 之后（或放到动画 Done 回调里）

### P1-6 后台会话失败对玩家完全不可见

- 位置：`sidecar/src/session.ts:2435-2438`（`error` 先清 activity，再 `if (!focused()) return`）
- 触发：后台会话上游报错、未配置 Key、`requiredTool` 未被调用、`conversation_not_found`
- 后果：图标从 running 直接回到普通 chevron（连 completed 都没有），切回去只有提问没有回答也没有错误；玩家无法知道这一轮失败
- 修复：后台错误也发 `conversation.activity`（可加 `error` 状态或 reason），并在切回时补一条可读的系统消息

### P1-7 左栏排序使用文件 mtime，改名/撤回/撤销压缩会把旧会话顶到最前

- 位置：`sidecar/src/agent.ts:743-750`（按 `updatedAt` 排序）、`2000-2028`（`updatedAt = statSync().mtime`）；改名写 session_info、`deleteHistory` / `undoCompaction` 重写文件都会刷新 mtime
- 触发：给三天前的会话改名，或撤回它的旧回合、撤销压缩
- 后果：旧会话排到最前，时间标却仍显示“3 小时前”；与 `docs/protocol-v1.md:1207/1247` 对 `updatedAt` 的定义矛盾
- 修复：排序用“最后一条回答的时间”（已有 `lastReplyTick` 或单独持久化 `lastReplyAt`），元数据编辑不要改它

### P1-8 `target` 产量无上限、编译全程无预算，可挂死 sidecar

- 位置：`sidecar/src/blueprint/dsl/ir.ts:65-67`（只校验 `rate > 0`，不查有限值/上限）、`sidecar/src/blueprint/dsl/compile.ts:45`（直接交给 `kb.plan`）、`sidecar/src/blueprint/factory.mjs:141-144`（`Math.min(...buildings.map(...))` 一次性展开）
- 实测：fixture KB 下 `compileIr(rate=200000)` 约 4 秒后 `RangeError: Maximum call stack size exceeded`；`rate=Number.MAX_VALUE` 时循环不会结束
- 后果：`runDsl` 的 2 秒/64MB 只覆盖 JS 求值，不覆盖编译；编译是同步的，会阻塞 sidecar 的所有会话
- 修复：给 `rate` 设现实上限（并校验 `Number.isFinite`）；把预算检查放进 `factory`/`layout` 的循环内部；用循环代替 `Math.min(...array)` 展开

### P1-9 硬校验不校验分拣器端点/槽位，P0-5/P0-6/P0-7 都能全绿

- 位置：`sidecar/src/blueprint/validate.mjs:133-147`（只查长度 1..3、参数一致、两端 z 相同）、`150-163`（只对目标是带子的连接查相邻）、`128-130`（只查建筑原点在区域内）
- 对照：`docs/plans/2026-11-02-蓝图生成重写方案.md` §4 明确要求“分拣器长度 1..3，端点落在所连对象”
- 后果：悬空分拣器、错槽位号、不存在的站口、副产物没有出口都能过“硬校验”；这是前面三处出图硬伤没有被测试发现的直接原因
- 修复：校验分拣器两端必须落在所连建筑/带子的合法槽位；校验物流站端口与 storage 角色；校验每个产物都有出口；越界检查覆盖占地/碰撞体，而不只是原点
