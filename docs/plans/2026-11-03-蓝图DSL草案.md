# 蓝图 DSL 草案（v0）

## 0. 定位

蓝图 DSL **就是 JavaScript 的一个子集**：源码是 JS，在 QuickJS 沙箱里执行，只注入一套声明式 builder API，执行结果是 IR（JSON），再编译成蓝图。

不另造语法，不写 parser。JS 负责“怎么写”，builder API 负责“只能写什么”，编译器负责几何与校验。

## 1. 设计原则

1. **AI 写意图，编译器写几何**：源码里没有绝对坐标、没有逐格带子。
2. **声明式靠 API 约束**：只注入 `target/raw/options/module/connect/group/station/constraint` 和纯函数辅助。
3. **产出 IR，不直接产出蓝图**：JS 执行 -> IR -> 编译（展开/摆放/连接/校验）-> 蓝图文本。
4. **诊断可操作**：错误落在模块/端口/约束上，带错误码、源码行号和建议。
5. **终检在游戏**：编译保证自洽，粘贴前仍用游戏 `CheckBuildConditions` 校验。

## 2. 源码示例

```js
// 电磁涡轮 60/min，从原矿
target('电磁涡轮', 60);
raw('铁矿', '铜矿', '石矿', '煤矿');

options({
  belt: '极速传送带',
  sorter: '集装分拣器',
  assembler: '制造台 Mk.III',
  smelter: '电弧熔炉',
  station: '行星内物流运输站',
  proliferator: 3,
  maxWidth: 200,
  maxHeight: 120,
  aspect: 2.5,
});

// 模块就是函数：一次定义，多次实例化
function 电机组() {
  const 电动机 = module('电动机', { machines: 'auto' });
  const 磁线圈 = module('磁线圈', { machines: 'auto' });
  connect(磁线圈.out, 电动机.in);
  return 电动机;
}

const 总装 = module('电磁涡轮', { machines: 'auto' });
connect(电机组().out, 总装.in);
```

最小源码：

```js
target('电磁涡轮', 60);
raw('铁矿', '铜矿');
```

编译器自动展开 BOM、算机器数、按阶段摆模块、出图、生成报告。

## 3. API

| 调用 | 作用 |
| --- | --- |
| `target(物品, 每分钟)` | 目标产物，可多次调用 |
| `raw(...物品)` | 外部原料；不写则由编译器按 BOM 推断 |
| `options({...})` | 全局选项：建筑选型、带宽、增产、上限、长宽比 |
| `module(物品, { machines, building, recipe })` | 声明一个模块，返回带 `in`/`out` 端口的句柄 |
| `connect(源端口, 目标端口, 速率?)` | 逻辑连接；速率省略时按下游需求算 |
| `group(名字, [模块...], { place })` | 分组与摆放偏好 |
| `station(名字, { kind, side })` | 指定原料/成品/中转站的位置 |
| `constraint(描述)` | 额外约束（如“原料入口在左侧”） |

辅助函数（纯函数，沙箱注入）：`range(n)`、`repeat(n, fn)`、`sum(list)`。

### 3.1 模块

- `module(物品)` 默认按知识库配方与机器档位展开；
- `machines: 'auto'` 让编译器按流量算台数；也可写固定数字；
- `building` 不写时按配方类型选（熔炉/制造台/化工厂/研究站/精炼厂）；
- 模块内部布局由模板生成（进料站上、机器行中、出料站下）。

### 3.2 连接

- 一个模块的输入端口按物品自动分配；超过模板端口数报 `E104`；
- 连接默认走物流站（本地供给/需求），后续版本支持模块间带子；
- 没写的连接由编译器按 BOM 自动补。

## 4. 允许与禁止

允许：字面量、变量、函数、`for`/`if`、算术与字符串拼接、调用 builder 与纯函数辅助。

禁止（沙箱不注入）：

- `require`、`import`、`process`、`fetch`、`fs`、`eval`、`Function`；
- `Date`、`Math.random`、`setTimeout`、`setInterval`；
- 任何 I/O 与网络。

执行环境复用项目已有的 QuickJS-WASM 沙箱（`run_script` 同一套），只额外注入 builder API；预算沿用调用次数/CPU/返回文本三重限制。

## 5. IR

JS 执行后得到一份纯 JSON：

```json
{
  "targets": [{ "item": "电磁涡轮", "rate": 60 }],
  "raw": ["铁矿", "铜矿"],
  "options": { "belt": "极速传送带", "maxWidth": 200 },
  "modules": [{ "id": "m1", "item": "电动机", "machines": "auto", "building": null }],
  "connections": [{ "from": "m1.out", "to": "m2.in", "rate": 360 }],
  "groups": [],
  "stations": [],
  "constraints": []
}
```

IR 是编译器的唯一输入；缓存、诊断、测试都针对它，不依赖 JS 源码。

## 6. 编译流程

```
JS 源码 --(QuickJS 沙箱 + builder)--> IR
IR --> 展开(BOM/机器数/流量) --> 摆放(模块货架) --> 连接(站连站)
   --> 校验(流量/几何/电力/规则) --> 蓝图文本 + 报告 + 诊断
```

1. **展开**：按知识库算配方、机器数（向上取整）、流量守恒；缺配方 `E101`，原料不可得 `E102`。
2. **摆放**：模块按行排布、端口朝固定方向；超宽换行；总尺寸超限 `E301`。
3. **连接**：MVP 用物流站；带子只做模块内部。
4. **校验**：流量/带宽 `E2xx`、几何/端口 `E3xx`、电力 `E4xx`、规则 `E5xx`。
5. **出图**：复用 `BlueprintBuilder` 与校验器，输出 `.txt` 蓝图 + `report`。

## 7. 诊断

```json
{
  "code": "E201",
  "where": { "module": "m1", "port": "in", "line": 12 },
  "message": "输入需求 2400/min 超过一条极速带 1800/min",
  "suggestion": "把电磁涡轮拆成两个模块，或把进料改成两条带"
}
```

错误码：

| 段 | 含义 | 例子 |
| --- | --- | --- |
| E0xx | 执行 | JS 抛错、超时、禁用 API |
| E1xx | 展开 | 没有配方、原料不可得、端口不够 |
| E2xx | 流量 | 超带速、分拣器不够快、供需不平 |
| E3xx | 几何 | 超宽高、模块重叠、端口对不上 |
| E4xx | 电力 | 工厂不在供电范围 |
| E5xx | 规则 | 超蓝图等级、科技未解锁、叠层超限 |
| W4xx | 警告 | 只能贴赤道附近、用了垂直带 |

AI 每轮拿到诊断，改源码后重新编译；编译是秒级的（不做搜索）。

## 8. 与现有代码的衔接

- 模块模板：复用 `sidecar/src/blueprint/factory.mjs` 的“进料站 + 机器行 + 出料站”；
- 出图：复用 `emit.mjs` 的 `BlueprintBuilder`；
- 校验：复用 `validate.mjs`，补端口/连通性检查；
- 知识库：复用 `KnowledgeBase.plan` 算机器数与流量；
- 报告：复用现有 `report` 字段（materials/energy/techs/limits/warnings）。

## 9. MVP 与里程碑

| 阶段 | 内容 | 验收 |
| --- | --- | --- |
| M1 | 沙箱 + builder + IR + 展开 + 站连站摆放 + 出图 + 报告 | 「target 电磁涡轮 60/min」一张图，游戏内可贴 |
| M2 | 模块模板库（熔炉/制造台/化工厂/研究站/精炼厂）+ 模块内带子 | 多阶段产线一张图 |
| M3 | 带子连接（同层 L 形）+ 拆张 | 中型产线不靠站 |
| M4 | 高架跨越 + 电力规划 + 完整诊断 | 复杂产线一张图 |
| M5 | 编辑器闭环：AI 写 → 编译 → 诊断 → 改 | 真实游戏验收 |

## 10. 待定问题

1. 源码文件扩展名（`.bp.js`）与存放位置：蓝图目录还是 sidecar 工作区；
2. 模块模板是否开放用户自定义（先内置）；
3. 连接默认走站还是走带（M1 站，M3 起带优先）；
4. 多目标 + 副产物的语法（`target` 多次调用，副产物自动进站）。

## 11. 几何模型与空间约束

DSL 不写坐标，但必须能表达空间意图；编译器必须有一套真实的几何模型来兑现或拒绝这些意图。

### 11.1 编译器的几何模型

1. **网格与层**：蓝图局部坐标 (x, y)，z 为高架层，`z=0` 主层、`z=1` 跨线、`z=2` 干线；每层单独做碰撞。
2. **坡与垂直带**：一格最多升半层；垂直带（原地升降）需要「超级磁场发生器」，由 `allowVerticalBelt` 控制。
3. **分拣器**：两端必须落在机器槽位/带子格上，长度 1–3；允许斜跨，但斜跨会带来纬度敏感，默认只走直角。
4. **碰撞**：机器用物理盒、带子用格 + 物理盒、物流站用 5×5 占地并豁免端口格（沿用现有 `validate.mjs` 的口径）。
5. **纬度**：同一蓝图在不同纬度实际尺寸不同；编译器按 `latitude` 选间距策略，并生成“只能贴赤道附近”的警告。
6. **朝向**：蓝图可旋转粘贴；编译器按目标长宽比选横/竖排，并提示旋转。

### 11.2 DSL 暴露的约束

```js
options({
  latitude: 0,               // 设计纬度；0 = 赤道紧凑
  elevation: 1,              // 允许的最高层：0/1/2
  allowVerticalBelt: false,  // 是否允许原地垂直带
  moduleSpacing: 'compact',  // compact | latitude-safe
  aspect: 2.5,
  maxWidth: 200,
  maxHeight: 120,
});
group('电机组', [电动机, 磁线圈], { place: 'near', side: 'west' });
constraint('原料入口在左侧');
```

约束只描述意图：分组、相邻、方位、层数预算、纬度、尺寸上限。坐标由编译器生成。

### 11.3 几何能力分档

| 档 | 能力 | 适用 |
| --- | --- | --- |
| G0 | 模块模板 + 货架摆放 + 站连站 | M1 |
| G1 | 同层带子连接（L/Z 形，直角转弯） | M3 |
| G2 | 高架跨越、层间升降、电力规划 | M4 |

达不到所需档位时，编译器给 `E3xx` 并说明缺什么，而不是硬出一张贴不上的图。

## 12. 搜索策略：构造优先，搜索兜底

编译器**需要搜索，但不是 handcraft 那种全局退火**。分三层：

### 12.1 构造（无搜索）

- 模块内部：模板直接生成（进料站/机器行/出料站）；
- 模块之间：按拓扑序货架排布，超宽换行；
- 连接：站连站直接放站，或同层 L/Z 形直接连；
- 复杂度 O(建筑数)，毫秒级。

### 12.2 局部修复（有界搜索）

构造结果违反约束时才启动：

- 调整换行点、模块顺序、分组位置；
- 站点重定位、端口换边；
- 带子重路由（逐网 A*，失败则拆线重来）；
- 预算：最多 N 次尝试 / 固定毫秒数，超时返回当前最好结果 + 诊断。

### 12.3 全局优化（可选，限时）

- 仅在显式开启 `optimize: true` 时运行；
- 模拟退火/局部搜索，目标是面积或利用率；
- 严格时间预算（如 30 秒），默认关闭；
- 结果不比构造解差才采用。

### 12.4 与 handcraft 的差别

| 维度 | handcraft | 本方案 |
| --- | --- | --- |
| 搜索对象 | 每台机器的位置 + 每条带的走线 + 电力 | 模块顺序/换行/站点位置（MVP 甚至没有） |
| 搜索空间 | 极大，退火多轮重启 | 被模板压缩几个数量级 |
| 耗时 | 分钟到小时 | 构造毫秒级，修复秒级，优化限时 |
| 失败行为 | 一直搜到时间上限 | 立即返回诊断（不可行原因 + 建议） |

### 12.5 编译契约

- 固定预算内必须返回：**一张可行蓝图**，或**可操作的诊断**；
- 不做“无限搜索直到成功”；
- 复杂度超限时建议拆张或放宽约束，由 AI 改源码后重编译。
