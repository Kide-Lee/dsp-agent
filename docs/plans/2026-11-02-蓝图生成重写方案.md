# 蓝图生成重写方案（布局 / 出图）

> 2026-11-02。起因：社群反馈“蓝图粘贴到游戏无效”。结论已用编辑器里的游戏实测确认。
> 范围：保留 KB 产线规划（机器数 / 配方），重写 sidecar 的布局、出图与校验。

## 1. 真机复现（Unity 编辑器 Play 模式）

测试对象：`dsp-handcraft` 3.1.3 的 headless 输出（`calculate` → `planLine` → `emitBlueprint`），
用游戏自己的 `BlueprintData` / `BuildTool_BlueprintPaste` 校验与粘贴。

| 用例 | 建筑数 | 游戏解析 | 粘贴结果 |
| --- | --- | --- | --- |
| 电磁涡轮 60/min（对照组） | 351 | header=OK / content=OK | 全部 Ok，成功放置 351 台 |
| 引力矩阵 60/min（quick 档） | 10968 | header=OK / content=OK | **拒绝粘贴**：`CheckBuildConditions` 返回 false |

引力矩阵 60/min 的失败明细（赤道、远离已有建筑）：

```
Ok=10558  Collide=258  ConnWithErrorBuilding=72  TooFar=80
按物品：2003 极速传送带=263，2013 极速分拣器=130，2308 原油精炼厂=9，2303 制造台=8
```

同一张蓝图在玩家当前位置（北纬约 15°）粘贴时，先被区域检查挡住：
`BlueprintAreaCrossTropic`（458×63 的区域跨回归线），`areaValid=false`，连预览都不给。

结论：

- 蓝图字符串本身没坏。头部、gzip、MD5、建筑记录都能被游戏读入。
- 贴在赤道也贴不上：蓝图内部有 258 处自碰撞、80 处连接过远、72 处连到异常建筑。
- 贴在非赤道直接报“跨回归线”，大蓝图只能贴赤道附近。

## 2. 根因（handcraft 侧）

1. 布局搜索把“分拣器超过 3 格”“带子断开”当**软惩罚**，不是硬约束：
   `src/plan/sorters.js` 里 `w.length > 3` 只推进 `tooLong`，`src/plan/layout/score.js` 只加 `P.tracks` 惩罚。
   大产线避不开时照样输出长度 4–7 的分拣器。
2. 出图后检查不完整：`emit/check.js` 抓到了 87 条分拣器长度，但没抓到 258 处碰撞和 80 处 `TooFar`。
3. Web 页面在 `check.ok=false` 时仍允许复制，只写“需注意 N 处”（`web/src/app.js`）。
   用户复制 → 游戏拒绝 → “粘贴无效”。

## 3. 重写边界

保留：

- `kb_plan` 的产线规划：阶段、配方、`buildingCount`、原料。
- 现有 mod 侧：写 `.txt`、打开蓝图浏览器、贴图后自检。

重写：`sidecar/src/blueprint/` 的布局、出图、校验。新实现自己写，不复制 GPL-3.0 的 handcraft 代码。

## 4. 架构

```
KB plan（阶段 + 机器数 + 原料）
  → 行带布局（rows / bus / 分拣器）
      每个阶段一行机器；行间共享总线；分拣器长度 1..3
  → 出图（复用现有 dsp-calc 兼容编码器）
  → 硬校验（贴进游戏前必须全过）
      · 建筑不重叠（含跨层）
      · 分拣器长度 1..3，端点落在所连对象
      · 带子逐格相邻，不成环、不跳格
      · 区域尺寸在 1000×50 内，且能在赤道贴下（高度上限单独限制）
      · 物品/配方 ID 都在游戏数据里
  → 失败则换行数/间距重排，最多 N 次，然后明确报错
```

预算：

- 单次生成默认 ≤ 8 秒（sidecar 同步调用），最多 3 次重排；超时返回“当前最好但未通过校验”的错误，不出包。
- 大产线先按阶段切分成多张蓝图（每张 ≤ 2000 建筑），避免一次贴 1 万+ 台。

## 5. 里程碑

- M5 真机回归：用编辑器 MCP 批量生成 → `BlueprintData` 解析 → `CheckBuildConditions` 全 Ok → 抽样真实粘贴。

## 7. M1 已完成：硬校验器

`sidecar/src/blueprint/validate.mjs`，出图前由 `planner.mjs` 强制执行；不通过就换行数重排，仍然不通过则报错不落盘。

碰撞规则用编辑器里的游戏实测（同一张图贴到赤道、远离已有建筑）：

| 组合 | 游戏结果 |
| --- | --- |
| 制造台 (10,10) + 带子 (11,10) | Collide |
| 制造台 (10,10) + 带子 (12,10) | Ok |
| 制造台 (30,10) + 制造台 (31,10) | 两台都 Collide |
| 制造台 (40,10) + 制造台 (42,10) | 两台都 Collide |
| 带子叠在同一格（竖直升降的 0.0016 错位） | Ok |

据此：带子按 1 格占地压建筑的占地格（物流站口位除外），工厂之间、带子之间用 `buildCollider` 物理盒。
碰撞体数据从游戏 `LDB.items.prefabDesc.buildCollider` 导出到 `sidecar/src/blueprint/colliders.mjs`。

对照：

- 现有 `blueprint_generate` 的 964 建筑蓝图：校验 0 错误；游戏 `CheckBuildConditions` 也是 964 全 Ok。
- handcraft 引力矩阵 60/min：校验 120 错误（87 分拣器超长、28 碰撞、4 断带、1 超高）；游戏报 410（258 Collide / 80 TooFar / 72 ConnWithErrorBuilding）——比游戏少，是因为贴图位置还有地形/矿脉碰撞，离线判不了；M5 真机回归时会补。

附带修复：`sidecar/vendor/dsp-calc/src/blueprint/parser.js` 的 `new DataView(decoded.buffer)` 没带 `byteOffset`，zlib 返回池化 Buffer 时会从池子起点读，解出上一张蓝图。

## 9. M3 提前完成：总线（混带）布局

`sidecar/src/blueprint/layout.mjs` 的 `layoutBus()`：

- 一条蛇形传送带穿过全部机器；机器在带子下方，一个输入分拣器（槽位 0）+ 一个输出分拣器（下游 ±1 格）。
- 机器只吃自己配方认的物品，所以一条混带就能喂多输入机器，不需要为每种原料各拉一条带。
- 原料在行首上方各拉一条短带，用带→带分拣器放到总线上（`emit.mjs` 新增 `addBeltSorter`）。
- 机器间距按两边碰撞体半宽之和取整，避免不同建筑相邻时贴在一起；行首/行尾留 2 格给转弯。
- 容量：按每台机器的消耗速率累加每个带段上的流量；超过所选带的容量就抛 `传送带最大容量`，由工具按 2..8 张拆分重试（沿用原逻辑）。
- 段顺序按依赖拓扑排序，支持分支/汇合（电磁涡轮 7 段、29 台机器）。

`planner.mjs` 的布局顺序改为：总线 → 线性链 → dsp-calc。

真机验证（编辑器游戏 `CheckBuildConditions`）：

| 产品 | 规模 | 结果 |
| --- | --- | --- |
| 电磁涡轮 60/min | 29 台机器 / 272 建筑 / 40×32 | ok=True，0 异常 |
| 齿轮 60/min | 3 台机器 / 52 建筑 / 40×8 | ok=True，0 异常 |
| 带→带分拣器 | 2 条带 + 1 分拣器 | ok=True，0 异常 |
| 跨带高架（z=0 与 z=1 同格） | 2 条带交叉 | ok=True，0 异常 |

## 10. M4：按容量拆张 + 8 秒预算

- `layoutBus` 支持**多产物**（一行配方多个产出，例如等离子精炼同时出氢和精炼油），容量改成“按物品排序事件、累计在途量”，不再假设一段只产一种物品。
- 容量超限时抛结构化错误（`code=bus-capacity`、`tiles=至少几张`）；`planner` 不再把它吞掉，交给工具拆分。
- `buildBlueprintTiles` 从错误的提示张数直接开始，不再从 2 张一路试；每次失败后按新的提示继续跳。
- 张数上限 256，总耗时超过 8 秒就报错并提示降产量/拆蓝图。
- 知识库层的容量报错（`中间产物 X 份，超过传送带最大容量 A * B = C`）也会被解析成提示张数。

实测（`.scratch/kb/kb-zh.json` 的完整物品表 + 测试 fixture 的建筑表；测试 fixture 跑 1200/min）：

| 产量 | 张数 | 机器数 | 耗时 |
| --- | --- | --- | --- |
| 60/min | 1 | 29 | 11ms |
| 600/min | 5 | 285 | 37ms |
| 1800/min | 13 | 871 | 355ms |
| 6000/min | 41 | 2870 | 858ms |
| 12000/min | 81 | 5670 | 1.7s |
| 24000/min | 162 | 11340 | 3.1s |

注：完整物品表那份 KB 缺少 `buildingId`，只能用 fixture 的 13 个物品做端到端；张数/耗时规律一致。

## 11. 总线布局的建筑兼容性闸门（M3 中途）

总线布局假设“机器正上方有中间槽位、分拣器长度 1”，只有制造台/熔炉/化工厂一部分建筑满足。
新增 `slots.mjs`（游戏 `prefabDesc.slotPoses` 导出）与 `busCompatible()`：

- 要求本地槽位里有 `|x| ≤ 0.3`、`z ∈ [0.9, 1.2]` 的槽位（正上方中间）。
- 要求平面碰撞盒半宽/半深 ≤ 2.5。

不满足就抛 `code=bus-unsupported`，planner 回退到旧布局器。
精炼厂 2308（槽位只在侧面/下方、碰撞盒深 3.6）、化工厂 2310、研究所 2901 等暂时走回退。

精炼厂的分拣器端点其实是**小数**（实例：机器在 (16,11)，槽位端点 (16,8.138)，长度 3），
`slotPoses` 与蓝图 `localOffset` 之间还差一个模型原点偏移；要支持这类建筑和物流站，
需要先把“小数端口”在出图器/校验器里跑通——这是下一步的工作。

## 12. 小数端口与精炼厂上线

- `ports.mjs`：精炼厂 2308 的 6/7/8 号端口偏移（从 88 个真实样本反解）：`(∓0.782, -2.866)`、`(0, -2.862)`。
- `emit.addPortSorter()`：机器一侧端点是端口真实小数坐标，带子一侧沿用端口横向坐标、取带子所在行；
  长度按 `floor(曼哈顿距离)`。分拣器记录与游戏一致。
- `busStageMode()` 分两种摆法：
  - `top`：正上方中间槽位（制造台/熔炉），机器朝 0、带子在上、长度 1；
  - `bottom`：只有下方中间槽位（精炼厂），机器转 180° 让端口朝上，用端口分拣器。
- 机器横向间距按 `ceil(ext.x*2)`，行距按 `yOffset + ext.z + 0.5` 取整（精炼厂行距 9）；
  机器离转弯列至少 `ceil(ext.x+0.6)` 格，否则会蹭到转弯带。
- 化工厂 2310 等槽位在侧面远端、又没有端口偏移数据的建筑仍回退旧布局。

真机验证（编辑器游戏 `CheckBuildConditions`）：

| 蓝图 | 规模 | 结果 |
| --- | --- | --- |
| 2 台精炼厂 | 49 建筑 | ok=True，0 异常 |
| 6 台精炼厂（两行+转弯） | 108 建筑 | ok=True，0 异常 |
| 3 精炼厂 + 4 制造台（混排） | 115 建筑 | ok=True，0 异常 |
| 电磁涡轮 60/min（工具路径） | 241 建筑 | ok=True，0 异常 |

## 13. 端口偏移表推广到化工厂/位面熔炉/研究所

从引力矩阵蓝图反解出的端口偏移补充进 `ports.mjs`：

| 建筑 | 端口（本地：dx, dy） |
| --- | --- |
| 2309 位面熔炉 | 上 0/1/2：(-1,2)(0,2)(1,2)；下 4/5/6：(-0.716 侧) |
| 2310 化工厂 | 上 0/1：(-0.803,1.828)(-1.605,1.827)；下 7/8：(-1.6,-1.83)(-0.8,-1.829) |
| 2901 研究所 | 上 0/2：(0.803,1.828)(-0.803,1.828)；下 7：(0,-1.829) |

`busStageMode()` 现在分三条路：

1. `top`：正上方有中间槽位且机器不大（制造台/熔炉）——整数槽位分拣器；
2. `port`：有端口偏移数据——自动选朝向（0° 或 180°）、输入端口和输出端口，机器离带子 `ceil(端口 dy + 1)`；
3. 都没有就 `bus-unsupported` 回退。

真机验证（`CheckBuildConditions`）：化工厂 3 台 98 建筑、位面熔炉 4 台 101 建筑、研究所 2 台 49 建筑，全部 ok=True、0 异常。

## 15. 真机粘贴回归 + 物流站连接语义

**真机粘贴**（不是预览）：在远侧用 `MoveToNextStage()` 落成预置建筑，再 `RemovePrebuildWithComponents` 清理。

| 蓝图 | 建筑数 | 实测 |
| --- | --- | --- |
| 齿轮 60/min | 52 | 生成 52 个预置，清理后为 0 |
| 精炼厂 6 台 | 108 | 生成 108 个预置，清理后为 0 |
| 电磁涡轮 60/min（工具路径） | 241 | 生成 241 个预置，清理后为 0 |

**物流站连接语义**（用预置→实体转换后 `ReadObjectConn` 回读）：

- 带子只要**贴着站**，声明哪个 `outputToSlot` 就连到哪个槽位：
  在 0 号口的格子放带子、声明 slot 5，回读就是 slot 5——游戏不校验带子与端口格是否对应。
- 同一个槽位被两条带声明时，只有一条能连上，另一条被丢弃。
- 结论：端口格映射（`STATION_PORT_CELLS`）只影响**外观**，不影响连接是否成立；
  真正卡住供货的是站的**槽位过滤配置**（站要配置“这个口出什么货”），这部分还没编码进蓝图。
