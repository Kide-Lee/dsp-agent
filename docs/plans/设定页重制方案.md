- 日期：2026-10-31
- 范围：mod 侧设置界面（游戏原生 `UIOptionWindow` 内）与其所需的 sidecar 协议/配置增量
- 配套草稿：[设定页草稿.html](设定页草稿.html)（纯静态预览，不是最终 UI）
  - 预览图：[通用](设定页草稿-通用.png) · [快捷键](设定页草稿-快捷键.png) · [会话](设定页草稿-会话.png) · [工具](设定页草稿-工具.png)
  - 直接用浏览器打开；左侧分区可点，`#model` / `#tools` 这类锚点可直接打开某一页
  - 开关、快捷键捕获、搜索、会话行 hover 都是真实可交互的，方便判断手感

## 0. 结论先行

1. **不注入 6 个顶栏页签**。只保留**一个**注入页签（`Icarus II`），页内用「左侧分区导航 + 右侧内容」做二级切换。
2. 分区生效方式分两类：通用 / 快捷键 / 工具 / 会话**即时生效**；模型保持**草稿 + 原生「应用设置」**。
3. 需要 2 个新协议消息（`tools.set` / `conversations.index`）与若干可选字段；先改 `docs/protocol-v1.md`，再改 C#/TS 与离线测试。
4. 除页签本身外，所有布局都在 `dsp-game/Assets/IcarusII/SettingsPage.prefab`；动态列表用模板，运行期只绑定与增删。
5. 三个快捷键都允许**自由绑键**；绑定到可打印字符时会吞掉该字符，组字过程中不触发。这些语义只写在本文与代码里，页内不再放说明性文字。

## 1. 现状（决定方案形状的事实）

| 事实 | 位置 | 对方案的影响 |
| --- | --- | --- |
| 设置入口是聊天窗右上角按钮，点击后先关聊天窗，再 `UIRoot.OpenOptionWindow()` 并切到注入页签 | `ChatWindow.OnSettingsButtonClicked` | 设置页必须活在原生窗口里，不能另起窗口 |

| 工具集只有一个构造点 `buildToolDefinitions()`，`ready.payload.toolCatalog` 与 `ensureSession` 共用 | `PiAgent` | 工具开关只要在这一个点过滤，目录与注册不会漂移 |
| 第三方 mod 桥总开关 `[Bridge] AllowThirdPartyTools` 目前只能改配置文件，改完要重启 | `PluginConfig` | 它属于「工具」范畴，天然该放进工具页 |
| 静态素材 `docs/assets/qq-group.png`（二维码）已在仓库 | `README.md` | 关于页需要把它打进 UI bundle |

## 2. 为什么不是 6 个顶栏页签

- 原生顶栏是 160px 一格的横排，没有换行与滚动；再塞 5 个页签会挤爆窗口顶部，且每个页签都要克隆一套「恢复本页设置」占位按钮与补间组。
- 游戏原有页签（画面/音频/游戏/语言）与 mod 的 6 个分区是不同层级的东西，平铺会让人误以为「通用」也是游戏自带页。
- 原生 `_OnUnregEvent` 按 `tabButtons.Length` 索引 `revertButtons` 且不判空，页签越多越容易在下一次游戏更新时炸掉（`ModelSettingsTab` 里已经为这个坑写过占位按钮）。

因此：**一个页签 + 页内左侧导航**，页签数与今天的「模型」页一致，注入逻辑几乎不用改。

## 4. 分区规格

### 4.1 通用

**权限（默认档位）**

- 三个互斥卡片：`只读` / `受限`（默认）/ `接管`，每张卡两行：档位名 + 一句话行为说明（沿用 `PluginConfig` 里 `PermissionLevel` 的配置注释文案）。
- 风险提示常驻在卡片下方：「只读：所有写操作都要确认；受限：risk 1 直接放行，risk 2 需确认；接管：所有写操作直接执行」。
- 写入路径与聊天窗右下角的「权限」下拉**共用**同一条：`config.set.permissionLevel` + `PluginConfig.SetPermissionLevel` 本地兜底。不要出现第二套写逻辑。
- 回答进行中改档位时提示「下一回合生效」（协议 A.1：`config.set` 在回合结束后生效）。
- 实现细节：卡片本身是 prefab 里的三个 `Toggle`（`UIToggle` 套装）或三个按钮 + 选中态图，**不要**运行期建节点。

**版本**

| 行 | 取值 |
| --- | --- |
| 插件 | `Plugin.PluginVersion`（1.0.0） |
| sidecar | `ready.payload.serverVersion` + 连接状态/延迟；未连接显示「未连接」 |
| 协议 | `ready.payload.protocol`（v1） |
| 游戏 | `GameRefs.GameVersion`（0.10.30.3100） |
| BepInEx | `Chainloader` 里的版本号（读不到就显示 `—`） |
| 数据目录 | 解析后的 `DataDir` |

两个按钮：

- **复制诊断信息**：把上面几项 + 操作系统描述拼成一段文本进剪贴板，方便贴群里。
- **复制数据目录路径**：只复制，不提供「打开目录」——Proton/Windows 下打开文件管理器不可靠。

### 4.2 快捷键

| 项 | 默认 | 可绑定 | 落在哪 |
| --- | --- | --- | --- |
| 打开 / 关闭聊天窗 | `R` | 任意单键，或 `Ctrl` / `Alt` / `Shift` + 键 | `[General] Hotkey` |
| 发送消息 | `Enter` | 同上 | `[Keys] Send` |
| 换行 | `Ctrl+Enter` | 同上 | `[Keys] Newline` |

**自由绑键怎么实现**

现状是「回车由游戏改写版 `InputField` 的 `OnNewLine` 派发」，其它键根本到不了那里，所以先前的方案只能限制在 Enter 家族。要放开，拦截点得换：

- 统一用 `KeyChord`（`KeyCode` + `Ctrl` / `Alt` / `Shift` 三个布尔）表示绑定，`Parse` / `Format` 一对，配置里存 `"Ctrl+Enter"` 这种字符串。
- **回车**仍走 `OnNewLine`：那一刻按当前修饰键算出 chord，命中「发送」就提交（沿用现有 `_submitPending`），命中「换行」就保留换行并跑复选框自动补 `[-]`，都没命中就让输入框按原生行为换行。
- **其它键**在 `ChatWindow.Tick` 里轮询 `Input.GetKeyDown`：`chord.IsPressedThisFrame()` 命中就执行。
  - 发送：与回车路径共用同一个提交函数。
  - 换行：调 `InputField.InsertGeneralString("\n")`（按光标插入、会替换选区），并复用「上一行以 `[-]` / `[+]` 开头就补复选框」的既有逻辑；否则换行绑到别的键时行为会和回车不一致。
- 可打印字符必须同时把它从输入里拦掉，否则「按 S 发送」会先把 `s` 打进输入框再发送。手段是给输入框装 `onValidateInput`：当本帧按下的正是该绑定键、且字符与该键对应时返回 `'\0'`，字符被丢弃，`Append(char)` 不会改文本。
- 这个判定依据是 `Input.GetKeyDown` 的**帧状态**，不是事件顺序，所以无论 `Plugin.Update` 和 `EventSystem` 谁先跑都成立；粘贴（`Ctrl+V`）与 IME 提交都不经过该键的 KeyDown，不会被误删。
- **组字过程中不触发**：`Input.compositionString` 非空时跳过发送/换行判定，否则拼音打到一半按到绑定键会把半成品发出去。

**行为定义（不是可选项限制）**

- 三个绑定两两不同；捕获到重复时直接提示「已被『发送消息』使用」，拒绝保存，不自动对调——对调在自由绑键下更难预期。
- 输入框聚焦时，**打开键**仍让位给打字（现有语义，`HotkeyService` 已实现）；发送/换行只在输入框聚焦时生效。
- 工具菜单（`/`）展开时，回车仍是「选中当前项」，不参与发送/换行。这是菜单的既有语义，改成跟随配置反而怪。
- 可打印字符（字母、数字、符号）允许绑，但会占用该字符：它不能再输入到聊天框。功能键、方向键、`Ctrl` / `Alt` 组合没有这个代价。页内不解释这一点。
- 与游戏按键（`R` 建造旋转、`Esc`、`Tab`、`Space`）重复时不拦截、也不提示，允许保存。
- 单键与 `Shift` 的区别要写清楚：`Shift+Enter` 与 `Enter` 是两个不同绑定。

**捕获交互**

- 点「修改」→ 该行变「按下新按键…（Esc 取消）」，整页吃掉按键：不触发打开键、不传给游戏、不写进输入框。
- 只按修饰键不算完成，继续等主键；10 秒无输入自动取消。
- 保存时与另一个绑定相同 → 直接拒绝，只给一句「已被『发送消息』使用」的即时提示，不展开解释。

**收尾**

- 「这一次回车要不要提交」收敛成一个判定函数 `EvaluateEnter()`，`OnInputEndEdit`、`_submitPending`、AskPanel 三处共用，避免同一个回车三套规则。

### 4.3 模型

- 内容与今天一致（左供应商列表 / 右编辑卡片 / 密钥状态点 / API 地址 / 模型列表 / 检测 / 获取可用模型 / 草稿 + 应用设置），**不改交互**。
- 唯一改动：容器从「页签内容根」下沉到「分区容器」，`SettingsPageView.Bind` 的前缀统一改写，并保留缺节点自检。
- 不做的事：不在这里加「删除全部密钥」、不做密钥明文回显、不做导入导出。密钥只写不读是既有硬约束。

### 4.4 会话

**要解决的问题**：玩家在多个存档里都聊过，现在只能看到当前存档那一条串；想清理旧存档的会话必须进那个存档。

**数据模型（现状 + 增量）**

- 会话文件：`<dataDir>/sessions/<saveKey>/<conv_*>.jsonl`，活动会话：`<saveKey>/active.json`。
- `saveName` 只在 `save.bind` 里当显示用，**当前不落盘** → 新增 `<dataDir>/saves.json`：`{ "<saveKey>": { "name": "我的档", "lastSeen": 1760000000000 } }`，只在 `save.bind` 时写。
- 目录名就是清洗过的 `saveKey`，所以扫 `sessions/*` 就能还原出所有存档；没有 `saves.json` 条目的存档显示为 `存档 3f2a91c4`。

**界面**

- 顶部工具条：搜索框（过滤会话标题）、开关「只看当前存档」、右侧计数「共 N 个会话 · M 个存档」。
- 按存档分组：组头 = 存档名 + `saveKey` 前 8 位（mono）+ 最后使用时间 + 会话数；当前存档带「当前」标签。
- 会话行：标题（未命名显示「未命名会话」）、消息数、更新时间；当前活动会话带「使用中」标签。
- 行内操作：**导出**（写 Markdown，见下）、**重命名**（行内变输入框，回车提交，Esc 取消）、**删除**（红色，走原生 `UIMessageBox` 二次确认）；空会话的导出置灰。
- 空态：没有任何会话时显示一句话 + 「回到聊天窗开始新会话」。

**协议与边界**

- 新消息 `conversations.index` → `conversations.indexed`，按存档分组返回。索引必须是**只读**的：不能调用 `ensureActiveConversation`（它会改 `activeConversationId`、甚至写 `active.json`，会污染当前会话状态）。
- `conversation.rename` / `conversation.delete` 增加可选 `saveKey`；缺省 = 当前存档。非当前存档时：
  - 允许重命名/删除；
  - 删除一律先拒绝 `busy`（正在回答时不动）；
  - 不切换活动会话、不改当前存档状态。
- **不做**：跨存档恢复上下文、在设置页里读会话正文。前者语义危险，后者需要另一套渲染。

**导出**

- 行内「导出」：把该会话写成 Markdown，落在 `<dataDir>/exports/<saveKey>/<标题>-<yyyymmdd-HHmm>.md`。
- 内容：标题、存档名与 `saveKey`、导出时间，然后逐回合的「你 / 助手」正文；思考与工具步骤收成一段引用块（工具名 + 参数截断 200 字），方便复盘又不至于把文件撑爆。
- 由 sidecar 写文件（只有它拿得到历史文本），响应回路径与字节数；mod 只负责提示「已导出到 …」并给「复制路径」。
- 空草稿（一条消息都没有）不导出，返回 `empty`，提示「这个会话还没有消息」。
- 文件名清洗：去掉 `\ / : * ? " < > |`，截断 60 字符；同名追加 `-2`、`-3`。
- 不导出 API Key；截图只留一行「此处有一次截图」标记，不写图片字节。
- 不做「导出全部会话」：一次一个，避免误操作一次性落一屏文件。

### 4.5 工具

**要解决的问题**：工具已经很多（游戏读/写、知识库、蓝图、脚本、第三方 mod），玩家没有地方看「模型现在能干什么」，也没有地方关掉不想让它用的。

**条目字段**（由 sidecar 生成）

| 字段 | 说明 |
| --- | --- |
| `name` | 工具 id（mono，等宽显示） |
| `label` | 中文短名（沿用 `ToolNames.Label` 的取值，避免两套命名） |
| `description` | 截断 160 字 |
| `group` | 游戏读取 / 游戏写入 / 知识库 / 蓝图 / 脚本 / 询问 / 第三方 |
| `access` | 权限标记：`只读` / `受限` / `接管`（由 risk 映射，见下表） |
| `source` | 内置 或 插件名（第三方工具显示「由 UXAssist 提供」） |
| `enabled` | 当前是否对模型可见 |

权限标记与 risk 的对应（标记的含义就是「在哪个档位下会被直接放行」）：

| 标记 | risk | 行为 |
| --- | --- | --- |
| 只读 | 0 | 不改存档，任何档位都直接执行 |
| 受限 | 1 | 可逆写操作；`受限` / `接管` 档位直接执行，`只读` 档位仍要确认 |
| 接管 | 2 | 改存档；只有 `接管` 档位直接执行 |

**开关**

- 写 sidecar `config.json` 的 `disabledTools: string[]`，**sidecar 是唯一权威**；mod 只回显 `config.state` 里的同一份。
- 过滤点只有 `buildToolDefinitions()` 一处；同时要覆盖 `run_script` 的 `dsp.call` 白名单（它取 `host.tools()`），否则脚本能绕开关。
- 任何开关变化都让 pi 会话重建（能力变化已有此约定），UI 提示「下一回合生效」。
- 关闭写工具不能替代权限档位：权限档位继续决定「要不要确认」。

**界面**

- 顶部：搜索框 + 分组筛选 chip（全部/游戏读取/游戏写入/知识库/蓝图/脚本/第三方）+「全部启用」。
- 不设「允许第三方 mod 工具」的主开关：总开关仍是 `icarus-ii.cfg` 的 `[Bridge] AllowThirdPartyTools`（改完需重启），页内只在第三方分组为空时显示一行灰色提示说明去哪改。
- 列表行：开关 + 中文名 + 工具 id + 权限标记 + 来源；标记只用文字与颜色（只读蓝 / 受限青 / 接管橙），不用 emoji。
- 列表上方一行图例：「标记表示该工具在哪个权限档位下会被直接放行」。
- 页脚常驻：「改动只影响模型看到的能力，不会修改数据」。

## 5. 跨分区交互规则

| 规则 | 做法 |
| --- | --- |
| 分区切换 | 只切 `CanvasGroup.alpha/blocksRaycasts`，不销毁不重建；每分区保留自己的滚动位置 |
| 底栏 | 每个分区一条：左是本页一句提示，右是这项设置落在哪个文件/键；模型页的「应用设置」也在这里（其它分区隐藏） |
| 危险操作 | 删除会话、恢复默认工具：走原生 `UIMessageBox`，不自绘确认框 |
| 焦点 | 进入设置页时清空 `EventSystem` 当前选中，避免按键落到上次的控件；快捷键捕获时 `VFInput` 不消费 Esc |
| 文案 | 全部走 `Strings.Get`，zh-CN/en-US 同步补齐；自绘文案节点不要挂 `Localizer`（会被翻译表覆盖） |
| 图标 | 只用游戏已有 sprite 或纯文字；禁止 emoji |
| 长文案 | 说明文字单行省略 + tooltip（原生 `UIButton.tips`） |

## 6. 协议增量（先改 `docs/protocol-v1.md`）

全部是**新消息或可选字段**，不改动 v1 既有字段语义。

| 变更 | 方向 | 载荷 |
| --- | --- | --- |
| `ready.payload.toolCatalog[]` 增加 `group` / `risk` / `source` / `enabled` | sidecar → mod | 可选字段，老 mod 忽略 |
| `tools.set` | mod ↔ sidecar | 请求 `{disabled: string[]}`；响应 `{ok, disabled, rebuilt, toolCatalog}` |
| `conversations.index` | mod ↔ sidecar | 请求 `{}`；响应 `{saves:[{saveKey,saveName,lastSeen,current,conversations:[{id,title,updatedAt,messageCount,isActive}]}]}` |
| `conversations.export` | mod ↔ sidecar | 请求 `{saveKey, conversationId, format:"md"}`；响应 `{ok, path, bytes, messageCount}` 或 `{ok:false, error:"empty"}` |
| `conversation.rename` / `conversation.delete` 增加可选 `saveKey` | mod → sidecar | 缺省 = 当前存档 |
| `config.set` / `config.state` 增加可选 `disabledTools` | mod ↔ sidecar | 老端忽略 |

`tools.set` 响应直接带回新的 `toolCatalog`，避免「先改再拉一次目录」两帧不同步。

## 10. 风险与未决

**风险**

| 风险 | 应对 |
| --- | --- |
| prefab 二进制，`git diff` 只显示 Bin，改坏难定位 | 先骨架后内容，两步各 dump 一次；锚点静态对比 |
| 原生页签数组契约（`revertButtons` 不判空） | 页签数保持 1 个，复用现有备份/回滚 |
| 回车语义散落在 `OnInputEndEdit` / `_submitPending` / AskPanel 三处 | 收敛成一个判定函数再改配置化 |
| 跨存档删除误删 | 二次确认 + 拒绝 `busy` + 只对明确选中的会话生效 |
| 关掉工具让模型「能力倒退」却不自知 | 页脚常驻提示 + 下一回合重建会话 |
| 二维码贴图发虚 | 导入设置：无压缩、无 mipmap、sRGB 开 |
| 可打印字符绑定会吞字符，玩家误绑后打不出那个字 | 页内不解释；误绑需手动改回，语义只记录在本文 §4.2 |
| `onValidateInput` 与 IME / 粘贴互相干扰 | 只在「该键本帧按下」时拦截；组字期间跳过判定；粘贴路径不经过该键 |
| 导出路径跨平台（Windows 与 Proton）写不进去 | 统一落在 sidecar 数据目录，失败时回 `io_error` 并提示路径 |

**未决（需要拍板）**

1. 通用页是否顺手加上「语言 / 流式输出 / 字号 / 窗口位置」这些目前只能改 `icarus-ii.cfg` 的项？
2. 注入页签的显示名用 `Icarus II` 还是更短的 `Agent`？
